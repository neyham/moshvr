# Show the real experience

The most useful demo answers one question: what is it like to use a terminal
inside Quest? Capture the running app, including actual input and transitions.
Keep branding separate from product screenshots.

## A 25–35 second walkthrough

| Beat | Capture | What it demonstrates |
| :--- | :--- | :--- |
| 0–7 s | A disposable shell session in the Home panel; run a short command | Native terminal use |
| 7–15 s | Switch to immersive mode and adjust the panel | Spatial placement and passthrough |
| 15–22 s | Scroll, then switch a local session tab | Controller or hand input |
| 22–30 s | Optional voice: record, STOP, inspect the composer, Send | The real transcription-to-command flow |

Record the app version, headset model and OS version with each capture.
Keep text large enough to read at a README content width of roughly 800 px.
Use a representative still linked to a hosted video; a short, lightweight GIF
can show a single interaction. Avoid large autoplay animations of an entire
session.

## Images for the README

Lead with a real immersive workspace still, followed by one or two details:
readable terminal output, useful input controls, and a clear Home/immersive
comparison. Use alt text describing the visible interaction.

The final README should link directly to a real demo. Until one exists, do
not add a dead Watch demo button or substitute an illustration for a capture.

## Privacy before export

Use a disposable host and sample output. Remove real hostnames, usernames,
addresses, notifications, SSH fingerprints, tokens and private terminal
history. Passthrough can reveal the room and other people; capture in a
controlled setting and review every frame. Keep raw footage outside the
public source repository and strip identifying metadata from final media.
